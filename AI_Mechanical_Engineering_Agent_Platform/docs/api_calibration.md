# SolidWorks API 标定手册

本机环境: SolidWorks 2023 (RevisionNumber 31.5.0)，GB 模板，第一角投影。这里记录**经实测标定**的 API 行为 —— 官方文档要么没写，要么写错了。内核代码按这些结论实现；新增或修改 COM 调用前先查本表，实测得到新结论后追加到对应小节，注明来源项目与日期。

来源缩写: **CFC** = CFC-650 铜箔清洗机 V2 (2026-09/10, 238 零件 / 39 装配 / 106 图)；**PG** = 行星齿轮减速器 (2026-09-24)；**旧平台** = AutoCADByAI V2.x (至 2026-10-09)。

**本平台未回归**：来源项目实测有效，但平台现有回归样例 (行星齿轮 6 件、M03 约 330 件) 走不到这条路径 —— 大型装配体 (> 500 零部件)、整机总装 A0 图、内存回收重启等只在清洗机整机上出现过。重构时对这些代码只做了移植，没有在平台上重新验证；第一个用到它们的设计跑通后去掉标记。

| 22 | 装配图比例随运行变化 | 自动序号的位置每次相差几毫米，偶尔还读回远在图纸之外的位置 (视图组连同注释读成 161×4706 mm)。行星齿轮装配图 1:1.5 实测 331 mm 对可用 326 mm，6 次运行中 2 次被判放不下而改用 1:2 (回归基准当场抓到) → 任何图幅之外 0.5 m 以上的读数视为无效并记日志；允许超出不多于一个注释外扩量 (6 mm)，是否真正出框由 PDF 版面审核判定；每次记录实测外框 | 2026-10-10 |
| 23 | 投影视图被移到父视图另一侧 | m=1.5 内齿圈 4 次运行中 2 次：侧视图建好时在主视图右侧 (x=0.250)，之后的重建把它移到左侧 (x=0.031，以主视图 x=0.141 为轴镜像)，压住图框，版面审核报出框；内齿圈两侧投影相同，看不出是哪一侧 → 建视图后与存盘前各核对一次实际位置 (投影视图只核对可移动的方向)，偏离 20 mm 以上即改回并记日志 | 2026-10-10 |

## 4. 环境与运行时

| # | 行为 | 结论 | 来源 |
|---|---|---|---|
| 1 | 专用实例 | 程序自行启动 SLDWORKS.exe，经 ROT 名称 `SolidWorks_PID_<pid>` 精确连接，绝不附着用户自己的窗口。`.cad/sw_pid.txt` 记 **PID + 进程启动时间**：PID 会被系统复用，只记 PID 时可能把用户后来打开的 SolidWorks 当成专用实例，进而退出或结束它 → 两项都一致才使用，退出 / 结束前再核对一次；旧格式记录一律不认。ROT 名称按整数比较 (旧代码用子串匹配，PID 123 会匹配到 `SolidWorks_PID_1234`) | CFC / 2026-10-10 |
| 2 | "输入尺寸值"用户选项 | 程序标注尺寸时会弹修改框 → 运行期间关闭，原值记在 `.cad/sw_pref_orig.txt`，结束时恢复并**删除记录** (否则用户之后自己改的值每次都会被改回旧值)；异常退出未恢复时下次沿用旧记录 | CFC / 2026-10-10 |
| 3 | 用户窗口占用文件 | 文件被占用无法覆盖 → 每次运行写新目录，从根上避免 | 本轮 |
| 4 | **文件过滤层包装 SLDPRT** | 本机曾有 8 个 SLDPRT 被加上 4096 字节外来文件头 (`88 7d 1c ?? 4f 00 08 00`, 正文不可读)，同一文件不同进程看到的长度不同；时间与 `LdMFilter` 运行吻合 (推断为透明加密类驱动, 未证实)。对外交付 CAD 文件前，先在无该软件的机器上确认能打开 | 旧平台 |
| 5 | .NET 10 + SolidWorks PIA | 早期绑定可用；**不能嵌入互操作类型** (.NET 不支持跨程序集 COM 类型等价)，内核、零件库、设计项目共用同一份 PIA | 本轮 |
| 6 | 静态类 `Run` | 类内若有名为 `Run` 的成员会遮蔽 `CadKernel.Run` → 内核中避免把方法命名为 Run | 本轮 |
| 7 | Python 解释器 | `%LOCALAPPDATA%\Microsoft\WindowsApps\python.exe` (应用执行别名) 可能排在 PATH 前面，在某些进程环境中直接以退出码 49 / 9009 返回、无任何输出 → `config/cad.json` 的 `python` 写解释器完整路径 | 2026-10-10 |
| 8 | 启动专用实例的句柄继承 | `Process.Start(exe)` 在 .NET 中默认 `UseShellExecute=false`，子进程继承调用方的标准输出句柄；SolidWorks 比 `cad` 活得久，一直占着调用方重定向输出的管道，以管道读输出的调用方 (PowerShell `*>`、自动化工具) 永远等不到结束 → 用 `UseShellExecute=true` 启动 | 2026-10-10 |

## 5. 防假成功的三道防线 (CFC)

SolidWorks 特征 API 在参数不合法时**不抛异常，只返回 null 或什么都不做**。内核在程序层面设三道防线，任何一道不过立即中止并报出零件号：

1. **每个特征后体积校验** (`Sk.Check`)：拉伸必须增加体积，切除必须减少体积。切除方向反、草图没闭合、特征完全落在已有实体内都会被抓住。
2. **孤立草图检查**：草图没有子特征 (未被消费) 即报错。
3. **实体数检查**：零件实体数必须等于设计值 (多材质件可为 2)。

装配级第四道：每个螺栓真实穿过被连接件的孔，螺纹孔按公称直径建模，**干涉检查兼作孔位校核** —— 漏孔、孔位错、孔径小、螺栓顶穿孔底都会报干涉。CFC 首轮检出 1030 处，修正后为 0。
