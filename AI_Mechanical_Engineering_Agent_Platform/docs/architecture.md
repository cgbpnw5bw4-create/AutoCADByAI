# 平台架构

本平台用程序驱动 SolidWorks 完成机械设计的建模、装配、出图、校核与交付。今后的建模任务都在同一个内核上完成，能复用的零件族不断沉淀进零件库。

## 1. 三层结构

```
src/CadKernel     内核 (通用、稳定, 唯一调用 SolidWorks COM 的程序集)
src/CadLibrary    零件库 (持续沉淀的参数化零件族与外购件样本)
src/CadProjects   设计项目 (每个设计一个子目录, 由 input/<任务>/design.json 驱动)
src/CadCli        命令行 cad (根目录 cad.cmd: 增量构建后运行)
python/           输出后处理 (只读写文件, 不调用 COM)
tests/CadTests    纯逻辑测试 (不连接 SolidWorks)
```

| 层 | 内容 | 变动频率 | 收录门槛 |
|---|---|---|---|
| 内核 | 专用实例与看门狗、草图上下文 (每个特征后体积校验)、零件流水线 (孤立草图 / 实体数 / 材质 / 质量覆盖 / 属性)、按需构建、变换矩阵批量装配、配合装配 (含齿轮配合)、GB 紧固件与紧固件组、零件图与装配图规则引擎、参数表、BOM、干涉、完整性检查、STEP 导出与身份核对、运行目录 | 低 | 已在真实项目中标定的 API 行为, 见 [api_calibration.md](api_calibration.md) |
| 零件库 | 渐开线齿轮、电机/法兰/螺栓圆细节造型、外购件样本 (轴承、联轴器、伺服减速电机、导轨、气缸、泵阀等) | 中 | 已在真实 SolidWorks 中建模并参与校核; 规则见 [library.md](library.md) |
| 设计项目 | 某台设备或某个部件的具体设计: 布局、自制件、装配关系、出图配置、专属校核 | 高 | 无 (设计本身) |

内核不知道任何具体设备; 零件库不依赖任何设计项目; 设计项目只调用内核和零件库。

## 2. 一次运行的流程

```
input/<任务>/design.json
   │  参数校验 (不连接 SolidWorks; 不合格直接退出)
   ▼
output/<时间>_<任务>/            ← 每次运行一个目录, run.json 记录每一步
   parts     零件            CadProject.BuildParts    (每个特征后体积校验; 孤立草图; 实体数)
   assembly  装配            CadProject.BuildAssemblies
   checks    校核            模型完整性 / 干涉 (兼作孔位校核) / BOM / 截图 / 设计专属校核; 零件数、外形、质量登记为指标
   drawings  工程图          零件图 + 装配图 (SLDDRW + PDF), 每张图须有尺寸 / 重新打开的参考检查
   export    导出            STEP AP214 (含颜色) + 身份核对
   post      后处理 (Python) 图纸版面审核 + 全套图纸合订 PDF
   回归基准                  有 input/<任务>/expected.json 时逐项比对 (见下)
```

- 每次运行开始时，流水线清空内核静态状态 (登记表、紧固件组缓存、出图目录)，再调用设计项目的 `Prepare()` 设置项目名、版本、日期等 —— 新运行与续跑一致。
- 任何一步抛异常即中止，已完成的产物保留，`cad resume <运行目录> --from <步骤>` 续跑。
- 校核不通过不中止 (产物仍可查看)，但运行最终状态为 `failed`。是否可信只看 `run.json`。
- 校核在每次运行中当场完成，不依赖代码哈希之类的历史证据。

### 回归基准

校核只能说明"没有报错"，说明不了"和以前一样对"：图纸比例变了、尺寸少了、剖视图多出伪直径，版面审核都不会报。所以每个回归样例在 `input/<任务>/expected.json` 保存一份**人工确认过的结果**，运行结束时由 `Baseline` 逐项比对：

| 比对项 | 来源 | 允差 |
|---|---|---|
| 必须出现且通过的校核 | `run.json` checks | — |
| 装配零件数、外形长 / 高 / 宽 | `Checks.Report` 登记的指标 | 计数相等，外形 ±1 mm |
| BOM 种数、件数、总质量 | `Checks.Bom` | 计数相等，质量 ±0.5% |
| STEP 实体数 | 导出步骤 | 相等 |
| 设计专属指标 (如行星轮系最大残差) | 设计项目 `Run.Metric` | 由登记时指定 |
| 图纸清单，每张的图幅、比例、尺寸数、孔标注数、序号数 | `drawings/index.json` | 相等；多出或缺少图纸都算偏离 |

- 任何一项偏离，`回归基准` 不通过，明细写入 `checks/baseline.md`。步骤没有全部完成 (部分运行、只出部分图纸) 也不通过：部分运行证明不了回归。
- 结果**有意**改变时 (改进出图规则、修改设计)，先看图确认，再 `cad baseline <运行目录>` 重新生成；命令会先列出新旧差异，提交说明里写明原因。不得为了让基准通过而放宽允差或删条目。
- 基准记录的是结果数值，不是代码或文件的哈希：改代码而结果不变时无需更新。新设计没有基准时不登记这项校核。

## 3. 语言分工: C# 骨架与执行, Python 输出后处理

结论：**两种语言结合，以"谁调用 SolidWorks COM"划界**。

| | C# (.NET 10, 早期绑定 PIA) | Python |
|---|---|---|
| 职责 | 骨架、全部 CAD 执行: 会话、建模、装配、出图、BOM、校核、导出 | 输出后处理: 图纸版面审核 (PyMuPDF)、全套图纸合订与书签; 今后的报告图表、文档、视频编码也放这里 |
| 是否调用 COM | 是, 且只有内核调用 | 否, 只读写文件 |

理由：

1. **已验证资产在 C#**。铜箔清洗机的整套 C# 内核 (238 个零件、39 个装配体、106 张工程图、DXF、BOM、STEP) 在本机实测并标定了 20 余项 API 行为；改写成 Python 等于全部重新标定。
2. **SolidWorks 特征 API 参数多且静默失败**。`FeatureExtrusion3` 23 个位置参数、`FeatureCut4` 27 个，参数不合法时返回 null 而不报错。早期绑定在编译期检查参数个数与类型；Python 往往运行到中途才出错。旧平台 STEP 导出错文档的假成功，根因就是晚绑定参数封送错误。
3. **一个 SolidWorks 实例只能有一个驱动者**。两种语言同时驱动会抢选择集和活动文档。
4. **Python 的长处在文件后处理**。PyMuPDF、reportlab、matplotlib、python-docx、ffmpeg 等没有同样顺手的 C# 对应，且这些步骤只碰文件，边界清楚。

行星齿轮原项目是 Python + pywin32：齿形几何是纯数学，已移植到 C# (`CadLibrary/Gears.cs`) 并由测试逐段对照原 Python 输出；装配与运动学校核也移入 C#。其运动仿真 (Motion) 与有限元 (Simulation) 不在本轮"零件 / 装配 / 出图"范围内，接入时同样移植到内核，或作为附着专用实例的 Python 分析脚本 (在内核释放实例之后运行)。

## 4. 冗余分析与精简结果

旧平台 (V2.3, 提交 `5e08134`) 约 5.8 万行 C#，真实 CAD 能力停在单零件 (板、法兰、轴、夹套与 9 类特征)，没有装配体和成套图纸；两个参考项目各约 6~7 千行代码，做成了整机。差距主要来自以下流程，本轮均已移出主干 (历史版本仍在 git 中可查，见 [migration.md](migration.md))：

| 旧流程 | 问题 | 现在 |
|---|---|---|
| 历史证据绑定: 41 个源文件的合成哈希, 改任一行即须重跑 14 组真机采证 | 维护成本远超建模本身; V2.2-C/D 三周只做出轴与夹套 | 每次运行当场校核 (特征体积、实体数、孤立草图、完整性、干涉、STEP 身份、图纸版面) |
| 7257 行自检 + 34 个受保护布尔字段 + 能力回归闸 | 检查"代码以前是否对过", 并多次出现判据被换弱却仍报 true | 单元测试 + `cad doctor` 环境检查 + 回归样例的真实运行与回归基准 (`expected.json`, 比对结果数值) |
| CADModelSpec → FeatureGraph → BuildPlan → Handler → Adapter → COM 五层 | 一次特征调用穿五层 | 一层内核 API, 校核内建 |
| 7 个 SmokeRunner、7 个内部 Agent、网关、API、任务审批、Microsoft Agent 运行时、模型运行时 | 未产出过装配体或成套图纸 | 由 Claude Code / Codex 直接编写设计项目 (两个参考项目正是这样做成的) |
| 39 份阶段文档 + 每模块 4 份文档 | 文档维护超过代码 | 4 份文档 + 代码注释 |
| output/ 78 MB、evidence/ 17 MB 入库 | 仓库膨胀 | 运行目录不入库 |

保留并吸收的旧平台经验：STEP 必须核对身份 (`StepCheck`)、同一台机器上 SolidWorks 输出可能被文件过滤层包装 (见 api_calibration.md 第 4 节)。
