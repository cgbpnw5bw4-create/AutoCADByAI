# V2.2-D 轴类与夹套真实能力基线

本阶段在 `AI Mechanical Engineer Platform` 既有架构上闭合轴类、夹套真实 CAD 缺口，不扩展 Agent、模型运行时或工作流架构。V2.2-C 的历史报告与失败记录保留原样。

## 真实执行范围

| 零件族 | 本轮受证输入 | 建模与验收 |
|---|---|---|
| `shaft_basic` | 直轴 Φ40×180；阶梯轴基径 Φ40、总长180，后两段 Φ32×40、Φ24×30 | RightPlane 明确闭合半截面，唯一构造轴，360°实体旋转；独立检查三段长度110/40/30及直径、端口、同轴、单实体和体积 |
| `jacket_basic` | 外径140、内径120、长180 | TopPlane 原点圆，外体盲拉伸180、内孔盲切360；独立检查内外同轴面、两端内外圆口、包络、单实体和体积 |

尺寸单位均为毫米。当前零件族授权绑定精确参数和操作计划，其他尺寸、操作顺序、部分角度、薄壁、任意面、约束执行等仍须新增证据，不能从这三个样例外推。

## 修复内容

轴类保留单独的中心线步骤，但该步骤严格确认已创建的唯一构造轴，不重复创建草图。修复错误的 `ISketch.GetFeature` 假设：该接口没有此方法。草图关闭后取得的特征仅作为候选，通过 `GetSpecificFeature2` 与当次草图的 COM 身份一致性验证，再用于轮廓选择。

旋转使用 `IFeature.Select2(false,0)` 与 `ISketchSegment.Select4(true, mark=16)`，核对选中数量0/16/全部为1/1/2、构造属性、20个精确参数、返回特征类型、旋转角、非薄壁凸台、重建和单实体增量。两个长度实参使用 `double`，不依赖整数隐式封送。

夹套改用已经受证的圆形坐标与盲拉伸/盲切语义，删除旧的非执行语义参数。`direction=blind` 与既有盲切合同一致，其他方向仍拒绝。两族的默认计划明确进入 FeatureGraph；保留底层兼容名称和旧专用 Builder，旧夹套 Builder 仍不获得生产授权。

曲面包络不能取圆柱接缝顶点。几何 Reader 采用六方向 `IBody2.GetExtremePoint`，显式封送三个输出参数；不退回近似包围盒。新增截面验收从真实圆柱面和圆边检查位置、轴线、直径与开口，体积使用输入独立计算的固定容差。STEP 分割圆边可以重复，但不能出现未知截面、偏心或盲孔假通过。

## 证据链与拒绝机制

`Feature Registry → Verified Handler → SolidWorks API Evidence → Worker → SolidWorks Adapter → 几何验收 → QualityGate` 保持不变。

`PartFamilyProductionEvidencePolicy` 只服务本轮两个受限零件族。它绑定新清单的内容摘要、当前源码修订、输入、编译计划、逐节点 API 执行记录、实际 CAD 文件及两种独立重开报告。文件大小和摘要从实际产物生成，报告原值必须一致；STEP 必须通过物理交换格式检查。缺文件、换参数、换策略、过期源码或版本不符均拒绝，大小写族名不能绕过检查。

`SolidWorksEdgeProbe` 从本次连接的 `RevisionNumber` 读取重开版本，写入新的实测报告；不能将建模版本填入旧探针记录。生产授权读取报告后重新执行同轴、截面、端口和体积判定，而非只信任报告中的通过标志。正式主流程的构建报告携带计划和实测几何，ArtifactValidator 再次复算；删除族名、计划、实测或改成 `NotDeclared` 均不能降低验收等级。

`v2_1_a_real_execution_frozen` 保留为历史冻结状态字段，当前证据激活后应为 `false`。全局判定改为验证缺证据仍被拒绝，不再要求项目永久缺少夹套能力。受保护的能力基线文件未降低。旧拒绝测试使用显式缺证据夹具，原拒绝断言保留；另增加默认实证激活及全局通过测试。

设计约束的旧回归输入仍保留在 `PartFamilyRegressionModels`，仅证明领域模型、模板复用、编译与 dry-run；真实 Sketch 仍拒绝非空约束，并有直接负向测试。这些夹具不作为真实约束 API 证据。

正式入口还修复了普通建模请求错误携带空 `parameter_update_json` 的问题：无更新时省略该键，有更新时才序列化。Router 对显式空值的拒绝规则保留；CLI 输出真实失败原因，避免只有笼统的失败状态。

## 仅记录的历史问题

历史文件异常增加4096字节的来源尚未确定。本轮保护快照记录历史 CAD/evidence、审查记录及上一阶段正式产物的字节指纹，并在结束时重新核对。所有新候选及正式发布件亦在重开前后核对物理字节；不能通过改写旧 `size_bytes` 或摘要消除差异。

2026-09-29 收尾复核514份实际文件，其中290份受保护历史文件全部与初始快照一致。四个测试夹具仅由测试改写生成时间；确认无其他字段变化后，将本次输出另行归档并恢复原始文件。构建0警告、0错误；14组候选完成28次双格式重开，4组正式主流程完成8次双格式重开，最终验收全部通过。

保存失败且路径不可信时，可能留下尚不能安全认领的文档。本轮继续只关闭能证明属于当前操作的文档，使用唯一内部名称和真实路径身份核对；不关闭未知用户文档、不退出整个 SolidWorks。除非影响当前证据真实性，不扩大到会话清理重构。

## 复验入口

按 `dotnet build`、完整 `dotnet test --no-build`、CLI `self-check`、CAD evidence 验证的顺序运行。真实产物采集使用现有诊断 Runner、正式 `run-cad-workflow --input` 入口及只读探针；采集脚本要求成功构建日志、源码/DLL冻结，并禁止覆盖已有报告。`EvidenceAudit` 调用原生产指纹算法和验收规则，不重新实现或替换 hash 算法。

下一阶段优先复验当前三个受限输入与发布包，再逐个增加明确尺寸档案。装配、工程图、制造性和任意旋转形状不在本轮授权内。
