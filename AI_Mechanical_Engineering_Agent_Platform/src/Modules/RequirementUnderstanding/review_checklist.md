# 需求理解模块审查清单

## 目标与适用范围

本清单复核 [V2.3 工程规划闭环](../../../docs/v2_3_engineering_planning_loop.md) 中模型输出与原 CAD 质量链的交接，并保留 [V2.2-A 任务生命周期与审批闭环](../../../docs/v2_2_a_task_approval_lifecycle.md) 的恢复和业务收尾检查。适用于代码审查、无 COM 行为验证及执行代理提供的独立真实产物证据复核。

## 输入与输出

输入为当前差异、原任务及审批合同、[执行流程](execution.md)、[接口证据](api_evidence.md)、实际测试与自检报告。输出为带源码位置、触发条件和验证依据的发现清单；未执行项必须明确标记，不以推断填通过。

V2.3 输入另包括原需求、原模型响应、来源模式、工程计划、映射图和构建计划、同次工程/E2E报告与双格式独立重开记录。审查不得改写产物或 evidence，报告不能收录访问令牌和模型凭据。

## V2.3 工程规划审查步骤

- 核对显式 `engineering_planning=true` 才进入专用流程，复用现有 `ModelRuntime` / `IModelProvider`，没有第二套模型或 CAD Schema。
- 核对模型用途是 `DesignPlanning`，仅理解、规划和建议，没有 Worker/COM工具调用、API授权或执行图；参数投影直接使用既有 `CADModelSpec`。
- 核对原始 JSON 严格解析在兼容转换之前，未知/重复/缺字段、错误类型、空响应、长度和深度超限均阻断。
- 核对原文逐字符绑定、唯一明确尺寸及各自单位、模型参数一致性、受证140/120/180 mm档案、输出以及未知附加需求逐项检查；模型不能删掉原要求或用样例默认值补缺参。
- 核对数字文本仅在有限数值与原文及受证尺寸完全一致后规范化，`140.0` / `1.8e2` 等表示不能造成证据字符串失配，也不能成为补缺参、单位转换、改尺寸或换绑证据的借口。
- 核对假设、缺参、风险、非 `ready` 决定和另一条 CAD 输入冲突都拒绝；零下游执行，不回退默认零件，不用 HumanApproval 绕过。
- 核对平台通过原夹套模板、图校验和编译器产生 `FeatureGraph` / `SolidWorksBuildPlan`，并执行现有计划 Validator、Reviewer 与计划门禁后才交接原 CAD 路由。
- 核对 Verified Handler、API Evidence、Worker、Adapter、ArtifactValidator、几何、Reviewer、QualityGate、发布包与能力基线保留，没有绑定源码改动或旧 evidence 换绑。
- 核对 `plan_source=replay` 明确记录；替身和重放只能证明合同与给定响应路径，不能宣称实时模型稳定性。缺 Provider 必须失败关闭。
- 核对 dry-run 不启动 CAD，保持 `NotDeliverable`；真实执行以同次 E2E和发布质量结果裁决，双格式独立重开验证单实体、尺寸、同轴、端口、包络和体积。
- 核对只验收受限纯几何，不宣称材料、压力、承载、制造适用性或任意自然语言/尺寸支持，不新增产品运行时多 Agent、并行或通用工作流语言。

## V2.2-A 兼容审批审查步骤

- 核对 `chief-engineer` 仍是唯一公开入口，内部 Agent 经 `WorkflowEngine` 执行，宿主和 Agent 不直接调用 Worker。
- 核对审批同时绑定工作流、本次请求与步骤，匹配和消费原子完成；错误、重复、并发及跨等待重放不增加下游执行。
- 核对保存并恢复原任务上下文，连续审批保留完整步骤、具体决定和审计，预取消不丢失待审批项。
- 核对首次执行和恢复均进入 `CompleteWorkflowAsync`，批准后的有效输出不残留已解决的等待标记；拒绝、要求修订及后续失败不会被映射成完成。
- 核对原路由后处理和宿主 `QualityGate` 仍执行；无法批准的错误不能通过人工审批绕过质量链。
- 核对访问令牌仅首次返回，查询和提交都校验令牌，`submitted_by` 只作审计；Microsoft advisory 按任务复用，恢复不增加 LLM 调用。
- 核对单进程、同步首次请求及接受后断线继续等边界与阶段文档一致，未实现的持久化和 `R07` 类型交接未被宣称完成。

## 验证标准

执行代理统一提供构建、完整测试、定向自检及四个阶段行为字段的实际结果。逐项检查错误身份、双审批、并发、批准后失败、门禁打回与 advisory 复用反例；本轮验证不启动 COM。新增基线保护项可以保留，既有 `true` 能力不得降低。

V2.3 五项 `engineering_planning_checks` 及合法/非法规划行为回归在不启动 COM 的测试中验证；执行代理另提供正式工程入口与真实双格式重开证据。阶段行为、完整测试、全局 self-check、真实 CAD、实时模型稳定性分别裁决。模型配置缺失或实际调用未执行时保留未完成，不能靠重放或旧样例填通过。

## 常见失败与禁止事项

发现状态与报告不一致、审批身份失配或收尾缺失时，按 [失败修复](failure_repair.md) 输出具体阶段、原因、证据和复验命令。禁止把测试未执行写成通过，把平台检查通过解释为 CAD 可交付，或修改历史审查、只读 `reviewrep`、旧 evidence 以消除发现。

工程规划发现须包含原文触发条件与被阻断位置，验证无 Worker 执行。禁止删除输入风险、放宽原文校验、使用固定样例伪装模型理解、把计划通过映射为真实交付，或把材料/制造建议提升为验收结论。
