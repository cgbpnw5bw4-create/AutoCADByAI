## 5. 可靠性风险

### MEDIUM-001（新引入）：`RunGit` 存在管道死锁模式，5 秒超时守不住

**位置**：`src/PlatformCore/PlatformSelfCheckRunner.cs:2516-2546`

```csharp
var startInfo = new ProcessStartInfo("git")
{
    RedirectStandardOutput = true,
    RedirectStandardError = true,      // ← stderr 被重定向
    ...
};
using var process = Process.Start(startInfo);
var output = process.StandardOutput.ReadToEnd();   // ← 同步阻塞读 stdout
if (!process.WaitForExit(5_000))                    // ← 超时只发生在这一行之后
{
    process.Kill(entireProcessTree: true);
    return null;
}
```

**问题**：stderr 被重定向但**从未被读取**。若 `git` 向 stderr 写入的数据超过操作系统管道缓冲区（Windows 上通常 4 KB），git 进程会在写 stderr 时阻塞；此时 git 不再向 stdout 写数据也不退出，主线程卡在 `ReadToEnd()` 上永不返回。**`WaitForExit(5_000)` 那行根本执行不到**，所以超时护栏在这个失败模式下完全失效。

**这不是理论风险**：本仓库的 git 操作会稳定向 stderr 输出 `warning: in the working copy of '…', LF will be replaced by CRLF the next time Git touches it`——本次审查中我自己每次调 `git diff` 都看到一批。当前 16 个修改文件约产生 2 KB stderr，尚未触及缓冲区上限；但这是一个随文件数增长而逼近临界的距离，而不是一个安全的设计。

**风险**：`PlatformSelfCheckRunner.RunAsync` 永久挂起。self-check 是 CliHost 和至少 8 个测试的入口，挂死会拖垮整条 CI。按协议 P3（"外部进程控制 / 挂死风险 / 残留进程"）与 P0（"外部应用卡死"），这属于必须处理的可靠性问题。

**建议修复（最小改动，三选一）**：
1. 最简单：`RedirectStandardError = false`（`rev-parse` / `status --porcelain` 的 stderr 本就不需要）。
2. 或者读掉它：`var error = process.StandardError.ReadToEnd();`——但两个同步 `ReadToEnd()` 仍可能互相阻塞，不推荐。
3. 推荐：改用异步读取
   ```csharp
   var stdout = process.StandardOutput.ReadToEndAsync();
   var stderr = process.StandardError.ReadToEndAsync();
   if (!process.WaitForExit(5_000)) { process.Kill(entireProcessTree: true); return null; }
   return process.ExitCode == 0 ? stdout.Result.Trim() : null;
   ```

**附带说明（非缺陷）**：`RunGit` 在 git 不可用时返回 `null` → `ResolveSourceRevision` 返回 `"unknown"` → `ValidateRealAcceptanceReport` 只要求 `source_revision` 非空，因此仍能通过。这个降级是合理的，但请在 `solidworks_real_acceptance_protocol.md` 里声明"self-check 需要 `git` 在 PATH 上，否则 `source_revision` 退化为 `unknown`"——这是一条未声明的环境依赖。

### 其余可靠性面：全部通过

- **假成功**：`real_acceptance_report.json` 的实测行为是**完全诚实的**。当前磁盘状态下它输出：
  ```json
  "source_report_final_status": {
      "build_report": "Failed", "drawing_report": "MissingOrInvalid",
      "dimension_report": "MissingOrInvalid", "title_block_report": "MissingOrInvalid",
      "package_quality_report": "Failed" },
  "all_source_reports_passed": false,

  ```
  `deliverableStatus` 只在 `allSourceReportsPassed && 四个产物均非空 && package 报告说 Deliverable` 三者同时成立时才是 `Deliverable`；缺失报告经 `NormalizeEvidenceStatus` 归一为 `"MissingOrInvalid"`，**缺信息即判失败**。这正是我要求的方向反转。

- **无限重试 / 无超时外部调用**：COM 三阶段超时护栏未动；新增的唯一外部调用是 `RunGit`，有 5 秒超时（但见 MEDIUM-001）。
