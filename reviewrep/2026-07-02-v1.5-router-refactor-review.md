## 6. 低优先级问题 / 细节建议

### LOW-001（本轮新增，输入契约变化）：触发改为结构化后，自然语言请求不再触发 CAD

- 新 `ShouldRun` 需要：`solidworks_main_workflow` flag / SharedState 的受支持 `CADModelSpec` / 结构化 context 键 / 消息含精确串 `plate_basic_4holes`。因此一条"帮我建个 SolidWorks 板件"这类自然语言、无结构化输入、无精确零件名的请求**不会触发** CAD。
- **评估**：这是 ARCH-B' 的预期修复（消除泛化误触发），非缺陷；但属输入契约变化。建议在 CADModeling `execution.md` 明确"触发主 CAD 工作流需结构化输入或精确零件名"，避免调用方误以为自然语言即可。

### LOW-002（本轮新增）：不受支持类型的 SharedState spec + flag 会静默回退到 plate_basic_4holes

- 若 `solidworks_main_workflow` flag 为真但 SharedState 的 `CADModelSpec` 是不受支持类型，`ResolveModelSpec` 返回 null → `TryBuildRequest` 用默认 `CreatePlateBasicFourHolesSpec()`。即"请求了别的零件，却静默建成 plate_basic_4holes"。
- **评估**：当前仅支持单零件、且约束串标注 `plate_basic_4holes_only`，风险有限。但为将来多零件计，建议不受支持类型时返回 null（不触发）或记一条 warning，而非静默替换。
