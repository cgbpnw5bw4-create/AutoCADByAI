## 1. 总体结论

**结论: 通过**

本版本完成了平台最关键的未完成事项 — 真实 LLM Runtime 集成。核心交付:

1. **MicrosoftRuntimeAgentInvoker** — 实现 `IMicrosoftRuntimeAgentInvoker`，接入真实 LLM 模型
2. **MicrosoftAgentOutputMapper** — JSON 解析 + 安全边界守卫 (权限提升/Worker 调用/Agent 可见性)

4. **AgentFactory + RuntimePlatformFactory** — 仅对 chief-engineer 启用真实 Runtime
5. **Gateway 响应扩展** — 6 个 Runtime 元数据字段透传至外部
6. **Self-check 扩展** — 反射验证 Runtime 组件 + 可选烟雾测试

所有 V0.1-V0.6 不变式保持。self-check 全面验证 — 14 个新增 Real Runtime 字段。

## 4. 关键架构改进

### 4.1 Runtime-then-Workflow 双阶段执行

```
Gateway → chief-engineer (MicrosoftAgentAdapter)
  ├─ Phase 1: Real LLM Runtime (advisory only)
  │   → MicrosoftRuntimeAgentInvoker.InvokeAsync
  │     → IRuntimeModelClient.GenerateTextAsync (OpenAI-compatible HTTP)
  │     → MicrosoftAgentOutputMapper.Map (JSON → AgentOutput)
  │     → 安全守卫: 权限提升 / Worker 调用 / 可见性变更 检测
  │   → RuntimeMetadata (Provider/Model/Fallback)
  │
  ├─ Phase 2: Platform Workflow (authoritative)
  │   → ChiefEngineerOrchestrator.ExecuteAsync
  │     → SequentialWorkflowEngine
  │       → InternalAgentWorkflowStep × 4
  │       → QualityGate per step
  │     → InternalCollaborationReport
  │
  └─ Merge: runtimeOutput.Message + workflowOutput.Message
       → GatewayMessageResponse (with RuntimeMetadata)
```

### 4.2 安全边界 (五层防护)

| 层级 | 机制 | 文件 |
|------|------|------|
| 环境变量 | `AI_AGENT_RUNTIME_MODE` 默认 Mock，缺凭据自动降级 | RuntimeConfiguration.cs |
| Agent 白名单 | 仅 `chief-engineer` 可被 `CreateRuntimeAwareAgent` 包装 | AgentFactory.cs:44-47 |
| Agent 自检 | `InvokeAsync` 拒绝非 chief-engineer 调用 | MicrosoftRuntimeAgentInvoker.cs:46-56 |
| 输出守卫 | JSON 解析检测 `visibility:Public`/`expose_internal_agents`/Worker 引用 | MicrosoftAgentOutputMapper.cs:115-123 |
| Gateway 透传 | Runtime 元数据仅信息性，不改变可见性或权限 | AgentMessageDispatcher.cs:78-84 |

### 4.3 配置降级链

```
RequestedMode=Microsoft + 凭据完整 → EffectiveMode=Microsoft → 真实 LLM 调用
RequestedMode=Microsoft + 凭据缺失 → EffectiveMode=Mock + FallbackUsed=true → Mock 执行
RequestedMode=Mock (默认)          → EffectiveMode=Mock → Mock 执行
```

### I7 详情 (V0.5 遗留，V0.7 仍未修复)

`SequentialWorkflowEngine.cs:68` — `var retryDelay = _retryPolicy.GetDelay(retryCount)` 计算了延迟，但审计日志记录延迟值后直接 `continue`，缺少 `await Task.Delay(retryDelay)`。ExponentialBackoffRetryPolicy 的计算结果从未实际等待。

### I9 详情

`OpenAICompatibleModelClient.cs:13` — `_httpClient = httpClient ?? new HttpClient()`。默认 `HttpClient` 没有超时设置，`TimeoutSeconds` 配置未传递到底层 HTTP 调用。建议使用 `HttpClient.Timeout` 或 `CancellationTokenSource` 在调用层超时。

## 9. V0.7 独有设计亮点

### 9.1 MicrosoftAgentOutputMapper 安全检查

`Map()` 方法执行四层安全检查:

1. **权限提升检测** — `visibility: "Public"` 或 `expose_internal_agents: true` → 记录问题
2. **Worker 调用检测** — 任何包含 "Worker"/"SolidWorks"/"AutoCAD" 的推荐 → 拒绝
3. **Agent 白名单校验** — `next_recommended_agent_id` 必须在已知 Internal Agent 中
4. **JSON 解析失败降级** — 非 JSON 输出 → 包装为 Completed + 原始文本，不中断流程

### 9.2 反射-based Self-Check 策略

`RunRealRuntimeSelfChecks` 使用反射加载 `AgentRuntime.Microsoft.dll` 并验证:

- 类型存在: `MicrosoftRuntimeAgentInvoker`, `RuntimeConfiguration`, `AgentFactory`, 等
- 方法签名: `FromEnvironment(environment)`, `Map()`, `CreateRuntimeAwareAgent()`, `InvokeAsync()`
- 运行时行为: 缺凭据降级、权限提升拒绝、Worker 调用拒绝
- 可选烟雾测试: 当 AI_API_KEY 等环境变量配置时，实际调用 LLM 一次

此策略保持了 Contracts 项目对 Runtime 类型的零依赖 (即使在 self-check 中也是通过反射访问)。

### 9.3 中文 System Prompt

`chief_engineer.system.md` 是中文提示词，包含:
- 7 个 Internal Agent 白名单
- JSON 输出格式要求
- 明确的安全约束: 不操作 CAD、不调用 Worker、不绕过 Gateway/QualityGate
