## 4. 高优先级问题

### HIGH-001（延续 + 本轮扩大）：真实执行阶段（`ExecuteWithApplicationAsync`）仍无超时，且未设超时的执行面又扩大一条

- **位置**：`SolidWorksSessionManager.cs:115-137`（`ExecuteWithApplicationAsync` 直接 `return await action(...)`，无 `CancelAfter`/`WaitAsync`）；本轮尺寸构建经 `RealSolidWorksWorker.cs:249` → 同一路径执行。
- **现状**：上一轮已修连接/断开侧超时；执行侧未修。本轮 `docs/technical_debt.md` 第 7 行已把它登记为技术债（"后续增加更明确的真实执行超时边界"），且 `SolidWorksBuildPlan.cs` 本轮只加了尺寸字段、未加执行超时。
- **风险**：真实 SolidWorks 在**构建/加尺寸/保存/PDF 导出**阶段最易弹模态框（重建错误、"覆盖已存在？"、许可证、模板选择）。这些同步阻塞 COM 调用不感知 token，调用方将无限阻塞。V1.2 新增的尺寸链路（打开工程图 → 确认视图 → `CreateLinearDim4`/`ICreateDiamDim4` → 保存 → 导出）复用同一未设超时的执行路径，等于把"可能挂死的真实执行面"从 2 条（plate 构建、工程图）扩到 3 条。
- **为什么仍是 HIGH 而非 Blocker**：真实 CAD 默认关闭 + 多重开关；挂死只停住 smoke，不产错误产物、不假成功；且 Codex 已作为技术债透明登记。但风险面在**持续增长**，越晚修成本越高。
- **建议**：在 `ExecuteWithApplicationAsync` 套用与连接一致的 `Task.Run(CancellationToken.None)` + `WaitAsync(cts.Token)` + 孤儿清理，并在 `SolidWorksRuntimeOptions` 增加独立 `ExecutionTimeoutSeconds`。建议**在扩大真实执行运行频率（例如批量真实出图）之前**把它从技术债提升为必修项；若 V1.3 仍只在 smoke 手动触发，可继续按技术债规则"触碰即修"。

## 5. 中优先级问题

### MEDIUM-001（本轮新增，语义假成功风险）：尺寸为非关联 + 硬编码数值，门禁只证明"已放置"，不证明"数值正确"

- **位置**：`SolidWorksDrawingDimensionBuilder.cs:301-405`（`AddRequiredDimensions`）、`TryAddLinearDimension`（:407）、`TryAddDiameterDimension`（:443）。
- **问题**：
  - 五个尺寸（长 160 / 宽 80 / 厚 12 / 孔径 ⌀10 / 孔心距 120×40）用固定图纸坐标 + `CreateLinearDim4`/`ICreateDiamDim4` **非关联**创建，数值来自传入常量 `expectedValueMm`，而非从模型几何测量。
  - `ConfirmRequiredViews`（:487）在视图名不可读时**按创建顺序**回退指定 Front/Top/Right/Isometric（:508-518），并只记 warning；`ActivateDrawingView` 若激活到非预期视图，配合固定坐标，尺寸可能落在错误视图/空白处，但仍返回 display dimension 对象 → 判"成功"。
  - Validator/self-check 的通过条件只校验"5 个 `*_dimension_added` 标志为 true + SLDDRW/PDF/report 存在 + `final_status=Passed`"（`SolidWorksArtifactValidator.ValidateRealDrawingDimensionReport`、`PlatformSelfCheckRunner.cs:342-350`），即只证明"标注对象已创建 + 文件已落盘"，**不证明数值由几何得出、不证明关联、不证明落在正确视图**。
- **风险**：这正落在协议最重的"假成功"红线附近——"看似成功（图上有尺寸、smoke Passed）但实际数值是硬编码常量、与真实几何无关联"。若视图比例非 1:1，非关联标注显示值还可能与实际不符。下游若把"尺寸 smoke Passed"读成"工程图尺寸已验证"，即为误判。
- **缓解现状（值得肯定）**：Builder **如实**记录了 `dimension_strategy = IDrawingDoc.CreateLinearDim4_non_associative`，并写入 warning（`SolidWorksDrawingDimensionBuilder.cs:404` "使用 CreateLinearDim4 非关联中心距，后续可在 V1.3 之后补充可关联孔中心选取"）与视图回退 warning（:510）。因此这是**已披露的受限实现，而非隐藏的假成功**。对 V1.2"基础尺寸"里程碑而言可接受。
- **建议**：在 `dimension_report.json`、`SelfCheckReport` 尺寸字段以及 review_checklist 中**显式暴露**尺寸的语义边界，例如新增 `dimension_associativity: "non_associative"`、`dimension_values: "authored_constants"`、`dimension_geometrically_verified: false`，使任何"尺寸 smoke Passed"都不会被误读为"几何已验证"。V1.3 再引入可关联标注（选几何边/孔中心）时移除该边界标注。

### MEDIUM-002（本轮新增，测试缺口）：尺寸构建内部的失败/防假成功守卫缺纯单元测试

- **位置**：`SolidWorksModuleSkeletonTests.cs` 新增尺寸测试用的是 `TestSolidWorksDrawingDimensionBuilder`（测试替身，直接返回 Completed），未走真实 `LateBoundSolidWorksDrawingDimensionBuilder.CreateCore`。
- **问题**：已覆盖——安全开关拒绝（`RejectsDrawingDimensionsWhenSafetySwitchesAreMissing` 断言 `RealCadExecuted=false`）、失败阶段映射（`MapDrawingDimensionFailureStage`）、schema 序列化、默认关闭字段。**未覆盖**——`CreateLinearDim4` 返回 null → 抛异常 → `FailWithReport`（Failed）；保存/PDF 落空 → `IOException`。原因是 Builder 的 COM 调用层用静态 `TryInvoke(object,...)`，不像 plate 的 `SavePart`（注入委托，上一轮 TEST-1 已能纯单测）那样可注入，故内部守卫只能靠 opt-in 真机 smoke 覆盖。
- **风险**：尺寸构建的"防假成功"逻辑（null 尺寸不算成功、空文件不算成功）没有回归保护，未来改动可能悄悄回退。
- **建议**：将尺寸 Builder 的 COM 调用抽象为可注入的最小接口（类似 `ISolidWorksComActivator`），补"尺寸创建返回 null → Failed"与"保存空文件 → IOException 且无 `dimension_save_success`"的纯单测。可延后，但与 MEDIUM-001 相关，优先级建议高于其它技术债。
