## 5. 中优先级问题

### MEDIUM-001：默认值 fail-open —— "什么都不设"由 dry-run 变为真实执行，CI 安全靠约定

**位置**：`SolidWorksBuildPlan.cs:104-107`（`EnableRealExecution` 默认 true）；`CliHost/Program.cs:178-179`（`allow_real_cad_execution` 默认 true、`dry_run` 默认 false）。

**问题**：授权门结构未变，但三个输入的默认值全部翻转为宽松。后果：V1.7-V1.9 时"忘记显式开启 = 安全 dry-run"；V2.0 变为"忘记显式关闭 = 真实执行"。真实 CAD 是不可逆外部动作（启动 SolidWorks、写盘、占 COM）。

- **这是所有者要的开发机体验**（手动跑即真执行、可见），本身合理。
- **风险面在自动化 / 无人值守环境**：CI / 批量脚本 / 一台装了 SolidWorks 的 runner，若既没设 `SW_SELF_CHECK=1`、也没显式传 `dry_run=true` 或 `allow_real_cad_execution=false`，就会真启动 SolidWorks。当前 self-check 自身安全（传 `dry_run=true`），但保护是**约定**（"记得在自动化环境设 `SW_SELF_CHECK`"）而非**结构强制**。

**建议（不牺牲 default-on 便利）**：加一道**不依赖记得设开关**的结构性判据——真实执行前探测环境：无交互桌面 / headless / 检测不到 SolidWorks 注册 → 自动降级 preflight-only 并给明确提示。开发机（有桌面 + 有 SolidWorks）探测必然通过，真实执行照旧、可见；CI / 裸机结构性默认安全。配一条"未设任何开关 + 模拟无 SolidWorks 环境 → 不连接"的负向测试。
