## 3. MEDIUM-001 修复: 反射访问私有字段 → `internal` 属性

### 变更前 (脆性):

```csharp
// 反射访问私有字段 _httpClient
var httpClientField = openAIClientType.GetField("_httpClient", BindingFlags.NonPublic | BindingFlags.Instance)
    ?? throw new MissingFieldException(...);
var httpClient = httpClientField.GetValue(configuredClient) as HttpClient;
openAIClientTimeoutConfigured = httpClient?.Timeout == TimeSpan.FromSeconds(7);
```

问题: 如果 `_httpClient` 被重命名、改为属性、或类型改为 `HttpMessageHandler`，self-check 静默失败，返回 `false`。

### 变更后 (稳定):

**OpenAICompatibleModelClient.cs:12** — 新增 `internal` 属性:
```csharp
internal TimeSpan ConfiguredTimeout => _httpClient.Timeout;
```

**PlatformSelfCheckRunner.cs:973-977** — self-check 改为访问属性:
```csharp
var configuredTimeoutProperty = openAIClientType.GetProperty("ConfiguredTimeout",
    BindingFlags.NonPublic | BindingFlags.Instance)
    ?? throw new MissingMemberException(...);
openAIClientTimeoutConfigured =
    configuredTimeoutProperty.GetValue(configuredClient) is TimeSpan configuredTimeout &&
    configuredTimeout == TimeSpan.FromSeconds(7);
```

**AgentRuntimeMicrosoftTests.cs:164** — 单元测试同步:
```csharp
var property = typeof(OpenAICompatibleModelClient).GetProperty("ConfiguredTimeout",
    BindingFlags.NonPublic | BindingFlags.Instance)!;
var configuredTimeout = Assert.IsType<TimeSpan>(property.GetValue(client));
Assert.Equal(TimeSpan.FromSeconds(3), configuredTimeout);
```

### 评估:

- **语义正确**: `ConfiguredTimeout` 名称清晰表达"这是配置的超时值"
- **`internal` 可见性**: 允许 self-check（通过反射）和同程序集测试访问
- **重构安全**: 如果 `_httpClient` 被重命名，只需修改 `ConfiguredTimeout` 的内部实现，self-check 不受影响
- **单元测试同步更新**: 保持一致性
- **异常类型更新**: `MissingFieldException` → `MissingMemberException`，兼容字段和属性

✅ **修复质量: 优秀。** 这是正确的重构方向——从"反射访问实现细节"转为"反射访问稳定的内部契约"。

## 4. MEDIUM-002 修复: 源码搜索 → 行为化检查

这是本轮最关键的改进。

### 变更前 (误判风险):

```csharp
var invokerSource = File.ReadAllText(...);
apiKeyNotLogged =
    !invokerSource.Contains("ApiKey", StringComparison.OrdinalIgnoreCase) &&
    !invokerSource.Contains("Authorization", StringComparison.OrdinalIgnoreCase) &&
    !openAIClientSource.Contains("ex.Message", StringComparison.OrdinalIgnoreCase);
```

根本问题: **从源码字符串猜测运行时行为**，而非**测量实际运行时行为**。如果代码中添加 `configuration.ApiKey is null` 守卫，包含 "ApiKey" 字符串，self-check 会假失败。

### 变更后 (行为验证):

```csharp
apiKeyNotLogged = await RuntimeFailureOutputDoesNotLeakCredentialsAsync(
    runtimeAssembly, openAIClientType, fromEnvironment);
```

**`RuntimeFailureOutputDoesNotLeakCredentialsAsync`** 完整流程 (1027-1079 行):

1. 用已知 secret `"self-check-secret-api-key"` 创建 RuntimeConfiguration
2. 构造真实 HttpClient（`StaticResponseHandler` 返回 401）
3. 通过反射实例化 `MicrosoftRuntimeAgentInvoker`
4. 调用 `InvokeAsync` → 走完整 Runtime 路径 → 前端异常 → catch 分支 → 生成 AgentOutput
5. 收集 **5 个输出通道**: `Message`, `Issues`, `Logs`, `RuntimeMetadata.FallbackReason`, 全部 `AuditLog` 条目
6. 断言 `Status == Failed`
7. 断言 **所有输出通道中不包含 `secret` 和 `Authorization`**

### 评估:

- **方法论根本性改进**: 从"猜代码会怎样"到"实际运行并测量"——这是测试方法论的正确方向
- **覆盖 5 个输出通道**: 不遗漏任何可能的凭据泄露路径
- **隔离性**: `StaticResponseHandler(401)` ——无需真实网络
- **未来安全**: 无论代码如何重构（属性重命名、日志格式变化、新 catch 分支），只要凭据不泄露到输出中，check 都通过
- **`StaticResponseHandler` 与测试文件轻度重复**: 不影响正确性，可在后续清理 commit 中共享

✅ **修复质量: 优秀。** 这是本轮所有修改中最根本的改进。
