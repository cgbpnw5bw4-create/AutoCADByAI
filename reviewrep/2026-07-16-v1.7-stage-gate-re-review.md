2. **把 CLI 入口判定抽成共享契约 `SolidWorksE2eCliContract`**（`CommandName`/`InputOption`/`IsInvocation`），CLI 和 self-check 引用同一真实逻辑。注释直书"避免用源码文本证明入口存在"。`Program.cs` 也从内联字符串比较改成 `SolidWorksE2eCliContract.IsInvocation(args)`。
3. **加了我建议但未强求的通用约束元测试** `V17SelfCheckUsesBehavioralEvidenceInsteadOfSourceTextMatches`：
   ```csharp
   Assert.DoesNotContain("cliProgramText", source, ...);
   Assert.DoesNotContain("routerText", source, ...);
   Assert.DoesNotContain("e2eRunnerText", source, ...);
   Assert.DoesNotContain("e2eReleaseBuilderText", source, ...);
   Assert.DoesNotContain("localAuthorizationProfileText", source, ...);
   ```
   这从"删这一批"升级到"扫描 self-check 源码、禁止这类变量再出现"。ARCH-R1 这次是被**根治 + 上锁**，不是又删一遍。

**RunGit 死锁彻底修复**（上轮条件二 / REL-R1）。`RunGit` 改为 `RunGitAsync`，`stdout` 和 `stderr` 都用 `ReadToEndAsync()` 并发读取，`WaitForExitAsync(timeout.Token)` 5 秒超时，超时即 `Kill(entireProcessTree)` 并 `await Task.WhenAll(stdout, stderr)` 排空管道。stderr 不再可能填满缓冲区把主线程锁死。配 `RunGitAsyncReturnsNoRevisionWhenGitReportsAnError` 测试。

**授权模型超出建议地实质修复**（ARCH-R2）。我上轮的观察是"单个 `config/solidworks.local.json` 即可打通真实执行全链路，纵深防御坍缩为单因子"，建议是"保留至少一个 profile 之外的独立因子"。Codex 做得比建议更彻底：
- `SolidWorksLocalExecutionProfile.ApplyToCurrentProcess` **删除**了对 `SW_ENABLE_REAL_EXECUTION` 和 `SW_REAL_MAIN_WORKFLOW_TEST` 的代设，只在操作者未设时提供 `SW_VISIBLE` 默认值。
- `Program.cs` 的 `ToGatewayContext` 里 `allow_real_cad_execution` / `dry_run` **只来自 input.json**，profile 不再覆盖。
- `examples/real_cad_plate_request.json` 显式加入 `allow_real_cad_execution:true` + `dry_run:false`。
- `docs/solidworks_real_acceptance_protocol.md` 明确要求操作者在 PowerShell 里显式 `$env:SW_ENABLE_REAL_EXECUTION="true"` 等。

结果：真实 CAD 执行现在需要**三个独立来源同时正确**——input.json（请求确认）+ shell 显式 export（环境确认）+ `config/solidworks.local.json`（profile 根授权）。单个文件不再能打通全链路，纵深防御恢复。配 `LocalProfileCannotEnableTheTwoCoreRuntimeConfirmations` 测试，断言 profile 授权后两个核心环境变量仍为 `null`。

**这些不是纸面修改，是能编译、能运行、有断言的修改。** 交叉验证：`PlatformCore.dll` 与 `PlatformSelfCheck.Tests.dll` 均为今日 15:07 新构建；`V17RealCadE2eSelfCheck` / `SolidWorksE2eCliContract` / `RunGitAsync` 三个新符号确认编译入 `PlatformCore.dll`；self-check 于 15:08 生成（晚于构建），`schema_version:1.7`、`final_status:Passed`，`source_revision = e52a486…-dirty` **与当前 HEAD `e52a486` 匹配**（上轮那个"报告写 3175e85 却在 e52a486 提交"的错配已消除）。
