## 4. 高优先级问题

### HIGH-001（延续，第 4 次扩大）：真实执行阶段仍无强制超时，未设超时的执行面已达 4 条

- **位置**：`SolidWorksSessionManager.cs:115-137`（`ExecuteWithApplicationAsync` 直接 `await action(...)`，无 `CancelAfter`/`WaitAsync`）；标题栏经 `RealSolidWorksWorker.cs:308` → 同一路径执行。
- **现状**：连接/断开侧已修（更早轮次）；执行侧未修。`docs/technical_debt.md` 已连续两段（V1.1、V1.2 Improvements）登记该项，规则为"保持真实执行默认关闭，后续在会话管理层补超时护栏"。
- **风险累积**：真实执行的未设超时路径已从 plate 构建 → 工程图 → 尺寸 → **标题栏**共 4 条。标题栏链路（打开工程图 → 读图纸属性 → 写自定义属性 → `ForceRebuild3` → 保存 → 导出 PDF）同样会在保存/导出/重建阶段触发模态框（"覆盖已存在？"、重建错误、许可证），同步阻塞 COM 不感知 token，调用方无限阻塞。**每加一个版本，挂死面 +1，越晚统一修成本越高。**
- **为什么仍是 HIGH 而非 Blocker**：真实 CAD 默认关闭 + 多重开关；挂死只停住手动 smoke，不产错误产物、不假成功；且已透明登记为技术债。
- **建议**：把 `ExecuteWithApplicationAsync` 的超时护栏（`Task.Run(CancellationToken.None)` + `WaitAsync(cts.Token)` + 孤儿清理 + `SolidWorksRuntimeOptions.ExecutionTimeoutSeconds`）**在真实链路开始批量/自动运行之前**从技术债提升为必修。由于该护栏是所有真实模式共享的会话层单点，一次修复即可覆盖全部 4 条路径，性价比高。

## 5. 中优先级问题

### MEDIUM-001（本轮新增，语义假成功风险，与 V1.2 尺寸同源）：标题栏"Passed"只证明属性已写入文档，未证明标题栏栏格可见地被填充

- **位置**：`SolidWorksDrawingTitleBlockBuilder.cs:375-419`（`PopulateTitleFields`/`WriteRequiredProperties`）、门禁 `SolidWorksArtifactValidator.ValidateRealDrawingTitleBlockReport`、`PlatformSelfCheckRunner.cs:356-364`。
- **问题**：
  - 标题栏字段大多为**授权常量**：`PartName="plate_basic_4holes"`、`DrawingNumber="PLATE-BASIC-4HOLES"`、`Revision="A"`、`DrawingDate=今天`；`Material` 取自 BuildPlan 参数或默认 `Q235`；仅 `Scale` 从真实图纸 `GetProperties2` 读取。对标题栏这类元数据而言，授权常量本身合理（不是几何测量），语义风险低于尺寸。
  - 真正的语义缺口在**最后一公里**：代码把 6 个字段写成文档的**自定义属性**（`CustomPropertyManager.Add3/Set2`），并 `ForceRebuild3`。但"标题栏栏格是否显示这些值"取决于图纸模板的标题栏 note 是否 `$PRP:` 链接到**这些确切的属性名**（`PartName`/`DrawingNumber`/…）。若模板标题栏链接的是别的属性名（或标准 GB/ISO 模板用不同命名），属性写入成功、回读一致，但标题栏栏格仍是空的。
  - 门禁只校验 `custom_properties_written=true`、`title_block_updated=true`（重建成功），**不校验属性与图纸模板栏格的链接/可见渲染**。因此"标题栏 smoke Passed"可能被下游误读为"图纸已有填好的标题栏"。
- **缓解现状（值得肯定）**：① 采用 `Get6` 回读比对值（`:431-434`），确保属性**确实写进了文档且值正确**——这是比尺寸更强的真实验证；② 产物描述如实写 "minimal title block metadata"；③ 报告字段名为 `CustomPropertiesWritten` 而非 `TitleBlockVisiblyPopulated`，部分披露了边界。
- **风险**：仍落在协议"看似成功但实际未达预期 CAD 输出"的语义区——"属性写好了"≠"标题栏看得见"。
- **建议**：在 `title_block_report.json` / `SelfCheckReport` / review_checklist 显式暴露该边界，例如新增 `title_block_fields_verified_in_sheet_format: false`、`title_block_population_strategy: "custom_properties_only"`，使"Passed"不被读成"标题栏按模板可见填充"。V1.4+ 若接入真实模板栏格链接校验（读取 note 文本确认含属性值）再移除该标注。

### MEDIUM-002（延续，测试缺口，本轮新增了未测的验证逻辑）：标题栏 Builder 内部失败/校验分支缺纯单元测试

- **位置**：`SolidWorksModuleSkeletonTests.cs` 标题栏 happy-path 用 `TestSolidWorksDrawingTitleBlockBuilder`（测试替身），未走真实 `LateBoundSolidWorksDrawingTitleBlockBuilder.ApplyCore`。
- **问题**：已覆盖——安全开关拒绝（`RejectsDrawingTitleBlockWhenSafetySwitchesAreMissing`，断言 `RealCadExecuted=false`）、schema 序列化、失败阶段映射、smoke runner 工程存在。**未覆盖**——本轮新增的 `WriteProperty` 回读比对逻辑（`Get6` 值不一致 → 属性 `Failed` → `custom_property_write_failed`）、`GetCurrentSheet` 为 null → `title_block_template_missing`、保存/PDF 落空 → `IOException`。原因同 V1.2：Builder 的 COM 调用层用静态 `TryInvoke(object,...)`，不可注入，内部守卫只能靠 opt-in 真机 smoke 覆盖。
- **风险**：本轮最有价值的"防假成功"改进（属性回读验证）**恰恰没有回归保护**，未来改动可能悄悄回退成"写入即成功"。
- **建议**：将标题栏/尺寸/工程图三个 Builder 的 COM 调用统一抽象为可注入接口（类似既有 `ISolidWorksComActivator`），补"属性回读不一致 → Failed"与"保存空文件 → IOException"纯单测。此项已在 `technical_debt.md` 以"后续抽取共享工具/补测试"形式登记，建议把"属性回读验证测试"作为其中优先项。
